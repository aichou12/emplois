CHARTE GRAPHIQUE


DESIGN SYSTEM INSTITUTIONNEL MULTI-PLATEFORME

Base commune pour les sites web, portails de services, applications mobiles, tableaux de bord et interfaces administratives.

Version préliminaire inspirée de l’identité visuelle du Ministère de la Fonction Publique, du Travail et de la Réforme du Service public.



1. VISION ET PÉRIMÈTRE

Cette charte graphique définit un système visuel commun, réutilisable et évolutif pour l’ensemble des plateformes numériques qui seront développées : sites web, portails de démarches, e-services, applications mobiles, espaces agents, tableaux de bord, systèmes de suivi et interfaces administratives.

L’objectif est qu’un usager reconnaisse immédiatement l’identité institutionnelle, quel que soit le service numérique utilisé. Les couleurs, les boutons, les formulaires, les titres et les messages doivent avoir une apparence et une signification cohérentes sur toutes les plateformes.

Principes directeurs

- Institutionnelle : l’interface doit inspirer sérieux, confiance, stabilité et service public.
- Accessible : les contenus doivent être lisibles pour des publics variés, sur ordinateur comme sur smartphone.
- Cohérente : une même couleur ou un même composant doit conserver le même sens partout.
- Simple : les démarches, formulaires et actions doivent être faciles à comprendre.
- Responsive : les écrans doivent s’adapter au mobile, à la tablette et à l’ordinateur.
- Évolutive : la charte doit pouvoir accompagner de nouveaux services sans être redessinée à chaque projet.


2. IDENTITÉ INSTITUTIONNELLE ET LOGO

Le logo du ministère constitue le signe principal d’identification visuelle. Il s’inscrit dans une identité nationale reposant notamment sur les couleurs vert, jaune et rouge.

Règles d’utilisation du logo

- Toujours conserver les proportions d’origine du logo.
- Ne pas étirer, déformer, tourner ou modifier les couleurs du logo.
- Prévoir un espace libre autour du logo afin de garantir sa lisibilité.
- Privilégier le logo en couleur sur fond blanc ou sur fond très clair.
- Éviter de placer le logo sur une image, un fond très chargé ou une couleur insuffisamment contrastée.
- Dans les plateformes institutionnelles, associer le logo du ministère à l’identité de la République du Sénégal lorsque le contexte le nécessite.



3. PALETTE DE COULEURS

Les couleurs ci-dessous constituent la base du système graphique. Les valeurs marquées « à confirmer » sont estimées depuis le logo, les captures et l’observation du site. Elles devront être validées plus tard dans les fichiers CSS ou avec l’inspecteur du navigateur.

3.1 Couleurs institutionnelles

Vert institutionnel

- RGB : rgb(0, 140, 69)
- Usage : actions principales, validation, boutons majeurs, sections institutionnelles, icônes positives, éléments de confiance.

Vert foncé
- Code : #006B35 —
- RGB : rgb(0, 107, 53)
- Usage : survol des boutons verts, éléments actifs, variantes sombres.

Jaune institutionnel
- Code : #FFC107 —
- RGB : rgb(255, 193, 7)
- Usage : boutons secondaires, liens de découverte, réseaux sociaux, éléments qui attirent l’attention.

Jaune foncé
- Code : #D99F00 — à confirmer
- RGB : rgb(217, 159, 0)
- Usage : état survolé ou actif des éléments jaunes.

Rouge institutionnel
- Code : #ED2939 — à confirmer
- RGB : rgb(237, 41, 57)
- Usage : erreurs, alertes, actions destructives ou accents visuels limités.

3.2 Couleurs neutres

Noir texte
- Code : #1D1D1B — confirmé
- RGB : rgb(29, 29, 27)
- Usage : titres, textes principaux, navigation et icônes sur fond clair.

Noir profond
- Code : #000000 — confirmé
- RGB : rgb(0, 0, 0)
- Usage : footer, zones à fort contraste et bouton de retour en haut.

Blanc
- Code : #FFFFFF — confirmé
- RGB : rgb(255, 255, 255)
- Usage : fond principal, cartes, contenus aérés et texte sur fonds foncés.

Gris texte secondaire
- Code : #575A7B — confirmé
- RGB : rgb(87, 90, 123)
- Usage : textes secondaires, informations complémentaires et métadonnées.

Bleu information
- Code : #EEF6FF — à confirmer
- RGB : rgb(238, 246, 255)
- Usage : panneaux d’aide, FAQ, informations neutres et encadrés d’assistance.

Gris bordure
- Code : #E5E5E5 — à confirmer
- RGB : rgb(229, 229, 229)
- Usage : séparateurs, champs de formulaire, traits discrets et limites de cartes.

3.3 Règles d’usage des couleurs

- Le vert est la couleur principale. Il représente l’action importante, la validation et la confiance institutionnelle.
- Le jaune est une couleur d’accent. Il doit attirer l’attention sans remplacer le vert comme couleur d’action principale.
- Le rouge doit être utilisé avec parcimonie : erreur, danger, rejet, suppression ou alerte.
- Le noir #1D1D1B est la couleur par défaut pour les textes sur fond clair.
- Le blanc sert à créer des espaces respirants et assure un bon contraste sur les fonds vert ou noir.
- Les tons gris et le bleu très pâle servent à structurer l’information secondaire.


4. TYPOGRAPHIE

Deux familles typographiques sans empattement sont recommandées pour conserver une interface moderne, claire et lisible.

Police pour les titres et mises en avant
- Famille : Poppins
- Graisse recommandée : 600, SemiBold
- Usage : titres, grands chiffres, boutons, libellés importants, appels à l’action.

Police pour les textes de lecture
- Famille : DM Sans
- Graisse recommandée : 400, Regular
- Usage : paragraphes, descriptifs, formulaires, listes, aides et contenus de lecture.

Base de texte déjà relevée

font-family: "DM Sans", sans-serif;
font-size: 16px;
font-weight: 400;
line-height: 22.4px;
letter-spacing: 0.5px;

Échelle typographique recommandée

- H1, titre de page : 36 à 40 px sur web ; 28 à 32 px sur mobile.
- H2, titre de section : 28 à 32 px sur web ; 24 à 28 px sur mobile.
- H3, titre de carte ou de bloc : 22 à 24 px sur web ; 20 à 22 px sur mobile.
- Texte courant : 16 px sur web et mobile.
- Texte secondaire : 14 px.
- Libellé de bouton : 14 à 16 px.

Règles typographiques

- Employer Poppins pour les titres et les éléments qui doivent être visualement dominants.
- Employer DM Sans pour les textes destinés à la lecture.
- Utiliser des titres hiérarchisés : H1, H2, H3, sans sauter de niveaux.
- Réserver les majuscules aux menus, boutons courts, labels et informations institutionnelles importantes.
- Conserver un interligne d’environ 1.4 à 1.6 pour les paragraphes.

5. COMPOSANTS RÉUTILISABLES

5.1 Boutons

Bouton primaire

- Apparence : fond vert institutionnel, texte blanc.
- Usage : action principale de l’écran.
- Exemples : Valider, Envoyer, Continuer, Enregistrer, Soumettre une demande.

Bouton secondaire

- Apparence : fond jaune institutionnel, texte noir.
- Usage : action secondaire, consultation ou mise en avant.
- Exemples : Voir plus, Consulter, Découvrir, En savoir plus.

Bouton contour

- Apparence : fond blanc, bordure verte, texte vert.
- Usage : retour, annulation non destructive, action moins prioritaire.
- Exemples : Retour, Annuler, Télécharger, Fermer.

Bouton danger

- Apparence : fond rouge, texte blanc.
- Usage : action sensible ou irréversible.
- Exemples : Supprimer, Rejeter, Annuler la demande.

Bouton désactivé

- Apparence : fond gris clair, texte gris, aucune interaction disponible.
- Usage : action qui ne peut pas encore être exécutée, par exemple tant qu’un formulaire obligatoire n’est pas rempli.

Règles communes pour les boutons

- Utiliser un rayon léger de 4 px.
- Employer un libellé court, clair et orienté action.
- Prévoir un état normal, hover, focus, actif et désactivé.
- Garder un contraste suffisant entre le texte et le fond.
- Prévoir une zone tactile d’au moins 44 × 44 px sur mobile.
- Ne pas utiliser le rouge pour une action ordinaire.

5.2 Cartes

Les cartes servent à présenter des services, démarches, actualités, statistiques, documents ou profils.

Règles observées

background-color: #FFFFFF;
color: #1D1D1B;
border-radius: 4px;
padding: 35.2px;
font-family: "DM Sans", sans-serif;
font-size: 16px;
font-weight: 400;
line-height: 1.4;
letter-spacing: 0.5px;

Règles de conception

- Fond blanc sur une surface claire ou colorée légère.
- Rayon d’angle léger de 4 px.
- Espacement interne généreux.
- Titre clair, description courte et action identifiable.
- Si la carte est cliquable, ajouter un état de survol et un focus clavier visible.

5.3 Panneaux d’information

Panneau information
- Fond bleu très pâle.
- Texte sombre.
- Icône informative facultative.
- Usage : aide, FAQ, consigne, information neutre.

Panneau succès
- Fond vert très pâle.
- Icône de validation.
- Texte vert foncé.
- Usage : demande envoyée, opération terminée, document ajouté.

Panneau avertissement
- Fond jaune très pâle.
- Icône d’attention.
- Texte sombre.
- Usage : information importante avant une action.

Panneau erreur
- Fond rouge très pâle.
- Icône d’erreur.
- Texte rouge foncé.
- Usage : champ invalide, soumission impossible, erreur serveur.

5.4 Formulaires

Les formulaires représentent un élément critique pour les e-services et les démarches administratives.

- Chaque champ doit avoir un libellé visible.
- Le placeholder ne doit jamais remplacer le libellé.
- Les champs doivent avoir un fond blanc, une bordure grise discrète et un état focus vert visible.
- Les champs obligatoires doivent être indiqués clairement, par exemple avec le mot « Obligatoire ».
- Les messages d’erreur doivent expliquer le problème et proposer une correction.
- Les formulaires longs doivent être découpés en étapes avec un indicateur de progression.
- Les pièces jointes doivent indiquer les formats et tailles acceptés.

6. NAVIGATION ET STRUCTURES D’ÉCRAN

6.1 Navigation commune

Chaque plateforme devra reprendre les mêmes principes de navigation :

- Un en-tête institutionnel avec le logo et l’identité du service.
- Une navigation principale avec des libellés courts et compréhensibles.
- Un bouton principal visible pour l’action la plus importante.
- Un menu mobile clair lorsque l’espace réduit.
- Un fil d’Ariane dans les portails à plusieurs niveaux : Accueil / Service / Démarche / Étape actuelle.
- Un footer institutionnel qui rassemble les contacts, liens utiles et accès aux services.

6.2 Écrans à standardiser

La charte doit guider la création des écrans suivants :

- Portail web public : header, recherche, services, actualités, FAQ, footer.
- Catalogue d’e-services : cartes de services, filtres, recherche, catégories.
- Connexion et création de compte : champs, lien de récupération, aide, sécurité.
- Application mobile citoyen : accueil, accès rapides, suivi de demandes, notifications, profil.
- Espace agent : tableau de bord, statistiques, filtres, tableaux, actions administratives.
- Formulaire de démarche : étapes, champs, upload de documents, validation, confirmation.
- Suivi de dossier : statut, chronologie, documents, messages et actions autorisées.
- Pages système : chargement, état vide, erreur 403, erreur 404, erreur 500 et maintenance.



7. RESPONSIVE ET ACCESSIBILITÉ

La charte doit être pensée « mobile first ». Les services doivent rester accessibles avec un petit écran et une connexion limitée.

Mobile

- Affichage en une colonne.
- Marges latérales confortables.
- Boutons pleine largeur lorsque nécessaire.
- Zones tactiles d’au moins 44 × 44 px.
- Menu compact sans cacher les démarches essentielles.

Tablette

- Deux colonnes lorsque l’espace le permet.
- Navigation et formulaires adaptés au toucher.
- Cartes réorganisées sans perte de lisibilité.

Ordinateur

- Grilles de cartes, tableaux plus larges et espaces de travail étendus.
- Header et navigation plus riches, sans surcharger l’interface.

Accessibilité

- Garantir un contraste suffisant entre le texte et le fond.
- Ne pas transmettre une information uniquement avec une couleur.
- Ajouter une icône, un message ou un libellé à une couleur d’état.
- Assurer la navigation au clavier et un focus visible.
- Préserver une taille minimale de 16 px pour les textes de lecture.
- Utiliser un langage simple et des actions explicites : Envoyer, Continuer, Télécharger, Consulter le dossier.

09. SYNTHÈSE

Cette charte propose une identité numérique institutionnelle commune et durable :

- Le vert porte l’action principale et la confiance.
- Le jaune met en évidence les actions secondaires et les éléments d’attention.
- Le rouge est limité aux erreurs, alertes et actions sensibles.
- Le noir et le blanc assurent sobriété, contraste et lisibilité.
- Poppins renforce les titres et appels à l’action.
- DM Sans facilite la lecture des contenus, procédures et formulaires.

Cette première version constitue une base de travail pour l’ensemble des futures plateformes web et mobiles.
